# More GenUI 0.5.0 · 先猜一下，再看解析

浏览器手上有 ETag，缓存也过期了。服务器一定返回 304 吗？选“一定”的读者可能已经搞懂了新鲜度，只差分清谁来验证资源有没有变。现在练习可以针对这个选项给提示，让读者带着线索再判断一次。

## 在回答里放一道题

扩展和 Harness 的离线沙箱都提供 `genui.quiz.mount(container, config)`。一次挂载一个练习，题目前后可以照常放图解或代码。

- 练习需要稳定的 `id` 和有序的 `questions`。每题提供 `id`、`prompt`、`options`、`correct` 和 `explanation`。
- 每个选项提供 `id`、`text`，每个错误选项还需要自己的 `hint`。`correct` 填正确选项的 ID。ID 使用 1 到 64 个字母、数字、下划线或短横线。
- 宿主处理提交、重试、揭晓和下一题。末题揭晓后即可重新开始。配置出错时，界面显示原因，并通过已有的“修复”入口请求修正。
- 当前题、选择和反馈阶段随应用实例和练习 ID 保存。修改某个练习的题干、选项、解析或题序后，它会从头开始。同一应用里其他练习的进度单独保存。

[HTTP 缓存三题](../../examples/cache-prediction.html) 从“要不要发请求”一路问到“验证之后返回什么”。[二分查找单题](../../examples/binary-prediction.html) 只问一次区间，适合插进算法讲解中间。

## 三条手测提示词

打开扩展，每条用一个新对话。提示词刻意保留日常问法，方便观察模型会在哪一步出题。

| 把这句话发给 DeepSeek | 观察什么 |
| --- | --- |
| 我刚学完 HTTP 缓存，出三道连续的小题测测我，覆盖新鲜缓存、ETag 验证和资源变更。让我先选。 | 故意选错一次。提示能否点出这次误判？重试、查看解析、下一题和重新开始能否走通？ |
| 我总把二分查找的左边界写成 mid。拿 [1, 3, 5, 7, 9] 找 7，带我推一遍，走到要改边界时让我先猜。 | 预测题是否恰好出现在更新边界前？提交后能否接着读懂 mid + 1 的理由？ |
| 用一句话解释什么是数组下标。 | 回答能否保持简短，直接讲清概念？ |

## 验收和回退

本地类型检查、生产构建、16 项快速测试及 1 条 Chromium 答题回归通过。浏览器用例覆盖刷新恢复提示、重试、揭晓、翻题、完成和重新开始，也检查了无效正确答案会显示题号和修复入口。三条提示词的官网生成效果留待人工观察。

扩展 ZIP 解压到独立目录，在浏览器扩展管理页加载。Harness 使用同版本 TGZ，安装步骤见[项目说明](../../README.md)。需要回退时，重新加载 0.4.0 扩展目录或重新安装 0.4.0 的 Harness 包。旧版沙箱无法运行调用 quiz 接口的新练习。
