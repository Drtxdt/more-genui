# More GenUI 0.4.0

DeepSeek 检索后，回答旁现在可以显示来源页的预览图。点击缩略图打开原网页。正文有明确引用时，扩展将图放在对应小节旁，窄屏改为上下排列。缺少段落位置时，图片收在文末的「来源预览」。每小节一张，每条回答最多四张。

扩展优先尝试结果中的图片，再读取页面的 Open Graph 或 Twitter 封面。站点图标、字标、过小图片和失败请求会跳过。只打开智能搜索按钮或在正文中贴链接，都不会触发配图。

## 更新与权限

解压扩展 ZIP，加载包含 manifest.json 的目录。如果已经加载项目的 .output/chrome-mv3，在扩展管理页点重新加载，再刷新 DeepSeek。更新会申请 HTTPS 网站访问权限，供后台读取检索来源及图片。内容脚本只注入 DeepSeek，扩展总开关同时控制配图。Harness 安装方式见 packages/harness/README.md，宿主版本继续锁定 0.2.1-rc.5。

后台单次只处理登记来源中的一项，省略凭据及 Referer，拒绝 IP 字面量、本地主机名和 HTTP 重定向。超时为 4 秒，HTML 限额 512 KiB，原图限额 2 MiB。缩略图按消息保存在本机，保留 7 天，总预算 10 MiB。缓存命中可恢复已展示的图，升级前的回答只查本地缓存。生成应用使用原来的离线沙箱。

## 修复

Fetch 和 XHR 均使用发送的请求体交接显式修复参数。流式末行围栏在正常收尾时确认，取消或错误时保留手动恢复入口。请求按消息标识绑定，结束两秒后释放临时源码，用摘要识别重建的应用。消息内部变化按批次处理。

## 验证与手测

类型检查和生产构建通过，16 项快速测试及 8 项 Chromium 扩展回归通过。用真实公开分享响应核实了 SEARCH.results、cite_index 和正文引用。该样本的图片字段只有 site_icon。对前三个实际来源页的读取均返回 200，其中两张代表图是 Kaggle 字标，一张是赛事图。原生结果直接提供文章图片的字段仍待更多真实样本核对。

浏览器回放使用脱敏的真实来源记录，受控的 SSE 分块、来源网页和图片。检查了引用定位、文末回退、坏图、窄屏和刷新恢复。连续追加 40 个文本节点，只增加一次局部扫描，全页发现次数没有增加。数值见 [本次记录](../evidence/v0.4-verification.json)。

真实官网新生成的三个问题留作手测。分享接口和来源页探测不能替代登录后实际生成验收。

1. 请联网比较两款适合入门的机械键盘，分小节说明各自特点并注明来源。看每小节图的位置，再点图核对网页。
2. 请联网查三个适合初学者的数据科学比赛，用一段话介绍。没有明确段落引用时，看文末的来源预览。
3. 请用一句话解释二分查找，不要联网。检查普通回答保持纯文字。
